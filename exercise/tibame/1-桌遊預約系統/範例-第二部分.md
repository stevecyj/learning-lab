# 桌遊預約系統（二）：以 SQLite 保存預約資料

來源：[exam-part2.ipynb](exam-part2.ipynb)

第二部分保留第一部分的指令與業務規則，但把 `games` 字典換成 SQLite 資料表。這樣預約狀態會寫入 `game5.db`，程式結束後仍可保留。

## 學習目標

- 建立 SQLite 連線與 cursor。
- 用 `CREATE TABLE`、`INSERT` 建立初始資料。
- 用 `SELECT` 查詢、用 `UPDATE` 修改預約狀態。
- 了解 SQL 的 `NULL` 對應到 Python 的 `None`。

## 從字典到資料表

第一部分的資料：

```python
games = {'雨聲': None}
```

第二部分改成 `reservation` 資料表的一列：

| id | game | user_id |
| ---: | --- | --- |
| 2 | 雨聲 | `NULL` |

對照關係如下：

| 第一部分 | 第二部分 |
| --- | --- |
| 字典 key：遊戲名稱 | `game` 欄位 |
| 字典 value：預約者 | `user_id` 欄位 |
| `None` | SQL `NULL` |
| 改寫 `games[game]` | `UPDATE reservation ...` |

## 初始化資料庫

```python
connect = sqlite3.connect('game5.db')
cursor = connect.cursor()
```

`sqlite3.connect()` 會開啟（或在不存在時建立）資料庫檔案；`cursor` 負責執行 SQL。

`init_games()` 做兩件事：

1. 用 `CREATE TABLE reservation (...)` 建立資料表，欄位有流水號 `id`、遊戲名稱 `game`、預約者 `user_id`。
2. 用三次 `INSERT INTO reservation (game) VALUES (...)` 新增預設遊戲。

每次資料異動後呼叫 `connect.commit()`，才會把交易中的變更確實寫入資料庫。

## 指令處理函式 `handle_msg`

函式把「誰在操作」和「輸入什麼」明確傳入：

```python
def handle_msg(user_id, msg):
```

相較於把 `user_id` 寫死在程式內，這樣較容易日後接上登入系統或測試不同使用者。

### 查詢尚可預約的遊戲

```sql
SELECT * FROM reservation WHERE user_id IS NULL
```

SQL 的空值必須以 `IS NULL` 判斷，不能寫成 `= NULL`。查詢結果逐列取出後，`game[1]` 是第二欄 `game`，因此可用來組成清單。

### 預約遊戲：參數化 `UPDATE`

```python
cursor.execute(
    'UPDATE reservation SET user_id = ? WHERE game = ?',
    (user_id, game_name),
)
connect.commit()
```

問號 `?` 是 SQL 參數位置；值以 tuple 另外傳入。這比把字串直接拼進 SQL 更安全，也能正確處理引號等特殊字元。

流程仍和第一部分相同：先確認遊戲存在，再確認 `game[2]`（`user_id` 欄）為 `None`，最後更新預約者。

### 取消預約

```python
games = cursor.execute(
    'SELECT * FROM reservation WHERE user_id = ?',
    (user_id,),
)
```

`(user_id,)` 是「只有一個元素的 tuple」；逗號不可省略。程式先把要取消的遊戲名稱放入 `canceled_game_name`，之後再逐一執行：

```python
cursor.execute(
    'UPDATE reservation SET user_id = ? WHERE game = ?',
    (None, game),
)
```

傳入 Python 的 `None` 時，`sqlite3` 會把它存為 SQL `NULL`。先收集查詢結果、再更新，是合理的做法：避免在還走訪查詢結果時又用同一個 cursor 執行另一個指令。

## 目前版本的執行注意事項

- `init_games()` 每次執行都會建立同名資料表；在同一個 `game5.db` 再跑一次通常會出現 `table reservation already exists`。練習時可刪除資料庫檔重新開始，或將建表改成 `CREATE TABLE IF NOT EXISTS` 並另外處理初始資料是否已存在。
- `SELECT *` 搭配 `game[1]`、`game[2]` 容易因欄位順序改動而出錯。較清楚的下一步是只查需要的欄位，例如 `SELECT game, user_id FROM reservation`。
- 查到無預約可取消時，目前程式不會輸出提示；可加入 `else` 回應「目前沒有可取消的預約」。
- Notebook 執行完成後可呼叫 `connect.close()` 關閉連線；較完整的程式也會把連線與 cursor 傳入函式或用 context manager 管理。

## 自我檢查

1. 為什麼 `WHERE user_id IS NULL` 不能改成 `WHERE user_id = NULL`？
2. 預約和取消預約後，少了 `commit()` 可能發生什麼事？
3. 為什麼單一參數要寫成 `(user_id,)`？
4. 哪一段程式把 Python 的 `None` 轉成資料庫中的 `NULL`？

### 參考答案

1. `NULL` 代表未知或不存在的值。用 `= NULL` 比較時，結果不會是 `TRUE`，因此 `WHERE` 無法選出這些資料；判斷空值必須使用 `IS NULL`。
2. 資料庫變更會留在尚未提交的交易中。其他連線可能看不到這些變更；若連線關閉或程式意外結束，變更還可能被回復，導致預約或取消結果沒有寫入資料庫。
3. `(user_id)` 只是加上括號的 `user_id`，不是 tuple。Python 的單一元素 tuple 必須寫成 `(user_id,)`；這樣 `execute()` 才能將其當成只含一個值的參數序列，對應 SQL 中的一個 `?`。
4. 取消預約時的這段程式把 `None` 傳給第一個 `?`：

   ```python
   cursor.execute(
       'UPDATE reservation SET user_id = ? WHERE game = ?',
       (None, game),
   )
   ```

   `sqlite3` 在綁定參數時，會自動將 Python 的 `None` 轉成 SQL `NULL`。

## 2. 目前教材不能直接完整重跑

notebook 保留的是成功執行時的歷史輸出，無法證明目前檔案與環境仍然齊全。現在至少有以下問題：

| 問題                      | 目前狀態                                                                    | 實際影響                                                   |
| ------------------------- | --------------------------------------------------------------------------- | ---------------------------------------------------------- |
| 資料庫名稱不一致          | notebook 連 `mydatabase`；`mysql-learning/.env.example` 建立的是 `practice` | 直接連線可能得到 `Unknown database 'mydatabase'`           |
| Python 驅動未列入專案依賴 | `pyproject.toml` 沒有 `mysqlclient`                                         | `import MySQLdb` 可能得到 `ModuleNotFoundError`            |
| CSV 路徑依賴工作目錄      | `2-exam_score.csv` 必須位於 kernel 目前工作目錄                             | 工作目錄不正確時會得到 `FileNotFoundError`                 |
| 刪除指令寫錯對象          | 程式寫成 `DROP DATABASE IF EXISTS STUDENTS`                                 | 它在刪名為 `STUDENTS` 的資料庫，不是在刪 `students` 資料表 |
| 執行環境版本不同          | notebook 記錄 Python 3.10；目前專案要求 Python 3.11+                        | 必須把驅動裝到現在 Jupyter kernel 使用的環境               |

其中一行誤把 `students` 當成資料庫刪除：

```sql
DROP DATABASE IF EXISTS STUDENTS;
```

`DATABASE` 指資料庫，`TABLE` 才能指定資料表。原程式已經連進 `mydatabase`；如果要重建其中的 `students` 表，應改成：

```sql
DROP TABLE IF EXISTS students;
```

一般應用程式不應每次啟動都刪表。刪表會清掉所有成績，而且 MySQL 的 DDL 會造成隱含提交，不能期待一般的 `rollback()`
把表救回來。建表 SQL 由管理者執行一次；Python 只負責資料的新增、查詢與修改。

## 3. 這套成績系統要先處理哪些問題

### 3.1 資料是否從入口就被約束

分數的業務規則是「整數且介於 0 到 100」。只在畫面上檢查不夠，因為 CSV、其他程式或人工 SQL 都可能繞過 Python。這裡需要兩層保護：

1. Python 在寫入前把文字轉成 `int`，並提供清楚的錯誤訊息。
2. MySQL 使用數值型別與 `CHECK`，拒絕任何漏網的非法值。

MySQL 8.4 會執行未標示為 `NOT ENFORCED` 的 `CHECK` 約束；條件為 `FALSE` 時，寫入會失敗。詳見
[MySQL 8.4：CHECK Constraints](https://dev.mysql.com/doc/refman/8.4/en/create-table-check-constraints.html)。

### 3.2 身分、機密與權限

原 notebook 把 root 帳號與密碼直接寫進檔案。這會讓密碼跟著 notebook 被分享、備份或提交，而且應用程式一旦出錯，就擁有刪除整個資料庫的能力。

帳號可按以下方式分工：

- `root`：只在第一次建立資料庫、帳號與資料表時使用。
- `grade_app`：Python 執行時使用，只授予 `SELECT`、`INSERT`、`UPDATE`、`DELETE`。
- 密碼：執行時輸入或由環境變數提供，不寫進 notebook。

MySQL 新帳號建立後預設沒有權限，必須再用 `GRANT` 指定範圍；可參考
[CREATE USER](https://dev.mysql.com/doc/refman/8.4/en/create-user.html) 與
[GRANT](https://dev.mysql.com/doc/refman/8.4/en/grant.html)。

### 3.3 SQL 是否參數化

以下是原 notebook 的更新方式：

```python
sql = "UPDATE STUDENTS SET ENGLISH = 99 WHERE NAME = '%s'" % ("sophia")
```

這裡的 `%` 是 Python 先做字串拼接，不是資料庫驅動的參數綁定。只要值改成外部輸入，就可能產生引號錯誤或 SQL injection。

參數化寫法會把 SQL 與值分開傳入：

```python
update_sql = "UPDATE students SET english = %s WHERE student_no = %s"
update_values = (99, "S011")
cursor.execute(update_sql, update_values)
```

執行順序是：

1. `update_sql` 只保存 SQL 結構，其中兩個 `%s` 是交給 `MySQLdb` 的值佔位符。
2. `update_values` 保存兩個要綁定的值：新英文成績 99，以及目標學號 `S011`。
3. `cursor.execute()` 把 SQL 與值分開交給驅動處理；不要替 `%s` 自己加引號。

`mysqlclient` 的 `MySQLdb` 用法可參考其
[官方使用指南](https://github.com/PyMySQL/mysqlclient/blob/main/doc/user_guide.rst)。

### 3.4 交易邊界與錯誤不能被吞掉

原 notebook 多處使用裸 `except:`，發生錯誤時只回滾，卻不顯示原因。結果可能是「畫面看起來跑完了，資料其實沒寫入」。

交易流程如下：

```text
開始交易
  ├─ 全部 SQL 成功 → commit → 資料一起生效
  └─ 任一 SQL 失敗 → rollback → 顯示或重新拋出原始錯誤
最後一定關閉 cursor 與 connection
```

具體分支例子：

- 寫入成績 86：資料型別與 `CHECK` 都通過，執行 `commit()`，資料保留。
- 寫入成績 101：`CHECK` 為 `FALSE`，MySQL 拒絕寫入，Python 執行 `rollback()`，同一批資料全部取消。
- 連線密碼錯誤：連線階段直接拋出例外，不會假裝成「查無資料」。

Python DB-API 規範明確區分 `commit()`、`rollback()` 與 `close()`；關閉尚未提交的連線會隱含回滾。詳見
[PEP 249](https://peps.python.org/pep-0249/)。

### 3.5 查詢結果不要依賴 `SELECT *` 的欄位位置

原程式用 `row[0]` 到 `row[7]` 取值。只要資料表插入新欄位或調整欄位順序，Python 就可能讀錯資料。

查詢時應同時做到兩件事：

- SQL 明列欄位：`SELECT student_no, name, ... FROM students`。
- 使用 `DictCursor`，以 `row["name"]` 讀值。

這樣便能用欄位名稱確定取得的資料，不會因為新增或移動欄位，造成後面的索引全部錯位。

### 3.6 小量或低頻查詢可直接用 MySQL 計算平均

原 notebook 把所有學生抓回 Python，再把字串逐一轉成 `float`
相加。這堂課只有 11 列資料，而且平均值只在練習流程中查一次，所以直接使用 MySQL 的 `AVG()`，避免把所有成績傳回 Python：

```sql
SELECT
    ROUND(AVG(chinese), 2) AS chinese_avg,
    ROUND(AVG(english), 2) AS english_avg,
    ROUND(AVG(math), 2) AS math_avg,
    ROUND(AVG(social_science), 2) AS social_science_avg,
    ROUND(AVG(science), 2) AS science_avg
FROM students;
```

這段程式的執行順序是：Python 把 SQL 送給 MySQL Server，MySQL 計算五科平均，再把一列結果傳回 Python。沒有 `GROUP BY`
時，MySQL 會把所有符合條件的列視為同一組；空表的 `AVG()` 會得到 `NULL`。詳見
[MySQL 8.4 Aggregate Function Descriptions](https://dev.mysql.com/doc/refman/8.4/en/aggregate-functions.html)。

這個查詢仍有成本。本文沒有 `WHERE`，所以 MySQL 必須處理所有學生的五科成績。MySQL 的 Query
Cache 已在 8.0 移除，因此 MySQL 8.4 不會自動保存這次 `AVG()`
的結果，供下一個相同請求直接使用。若 100 名使用者同時查詢，這條 SQL 可能執行 100 次。可用 `EXPLAIN ANALYZE`
檢查實際讀取列數、執行時間與迴圈次數。詳見 [MySQL Query Cache](https://dev.mysql.com/doc/refman/5.7/en/query-cache.html)
與 [`EXPLAIN ANALYZE`](https://dev.mysql.com/doc/refman/8.4/en/explain.html)。

多人頻繁查詢同一份統計時，不要改成把全部明細傳回 Python。那會讓 MySQL 照樣讀取資料，還增加網路傳輸、Python 記憶體與應用程式 CPU。應依需求選擇：

- 資料少、查詢頻率低，而且結果必須即時：直接執行 SQL `AVG()`。
- 許多請求會讀取同一份平均值：把結果放入應用程式快取，或建立保存 `sum` 與 `count`
  的彙總表；成績變動時必須同步更新或讓快取失效。
- 報表查詢量很大：把讀取導向 MySQL
  replica 或獨立分析系統，避免佔用主要資料庫；replica 採非同步複寫時，結果可能稍舊。MySQL 官方也把 replica 列為分散大量讀取與分析工作的做法，詳見
  [Using Replication for Scale-Out](https://dev.mysql.com/doc/refman/8.4/en/replication-solutions-scaleout.html)。

### 3.7 notebook 能否重現

判斷 notebook 能否重現時，還要逐項檢查：

## 4. `students` 欄位型別哪裡怪

### 4.1 原始設計與建議設計

| 原欄位   | 原型別          | 問題                                                                             | 這堂課建議                           |
| -------- | --------------- | -------------------------------------------------------------------------------- | ------------------------------------ |
| `ID`     | `INT(11)`       | `(11)` 是舊式顯示寬度，不是只能存 11 位，也不改變 `INT` 範圍                     | `INT UNSIGNED AUTO_INCREMENT`        |
| `NAME`   | `CHAR(20)`      | 姓名長度不固定，固定長度語意不合                                                 | `VARCHAR(100) NOT NULL`              |
| `GENDER` | `CHAR(20)`      | 範例只存一個字元，宣告固定 20 字元沒有意義；真實性別分類也不能未經需求分析就假設 | 視需求移除；本練習暫用 `CHAR(1)`     |
| 五科成績 | 全部 `CHAR(20)` | 數字被當文字，能寫入 `abc`；排序、範圍檢查與平均計算都不可靠                     | `TINYINT UNSIGNED` 加 `CHECK 0..100` |
| 字元集   | `utf8`          | MySQL 8.4 中是已棄用的 `utf8mb3` 別名                                            | 明寫 `utf8mb4`                       |

MySQL 整數後面的顯示寬度已棄用，而且不限制可儲存範圍；因此 `INT(11)` 應直接改成 `INT`。詳見
[Numeric Data Type Syntax](https://dev.mysql.com/doc/refman/8.4/en/numeric-type-syntax.html) 與
[Numeric Type Attributes](https://dev.mysql.com/doc/refman/8.4/en/numeric-type-attributes.html)。

MySQL 8.4 的 `utf8` 仍是 `utf8mb3` 的已棄用別名，新應用程式應使用 `utf8mb4`。詳見
[Unicode Character Sets](https://dev.mysql.com/doc/refman/8.4/en/charset-unicode-sets.html)。

### 4.2 `gender CHAR(20)` 的問題

這裡包含三個不同概念：

1. **SQL 儲存型別**：`CHAR(n)` 表示固定長度文字；`VARCHAR(n)` 表示可變長度文字。
2. **資料編碼**：`M`、`F`、`U` 或其他代碼是系統選擇的值。
3. **領域定義**：欄位究竟表示性別認同、生理性別、行政系統代碼，還是只是一份舊 CSV 的分類，必須由需求決定。

若契約真的規定只存一個固定代碼，`CHAR(1)` 才和資料形狀一致；`CHAR(20)`
既沒有提供更完整的領域定義，也讓讀 schema 的人誤以為會存 20 字元文字。

`CHAR(1)` 只忠實表達原練習檔目前使用 `m`／`f` 的單字元代碼，不能用來推論真實世界只有兩種性別。正式系統要先問：

- 成績查詢真的需要這個欄位嗎？不需要就不要收集。
- 是否允許未提供、未知或不願透露？
- 類別由誰定義，未來是否可能增加？
- 這是不是受隱私規範管理的個人資料？

如果選項會變動，可改用可空的 `VARCHAR` 加參照表；如果完全不參與成績功能，通常應移除它。本教學為了對照原資料，暫時保留
`gender_code CHAR(1)`，並把它視為教材代碼，不當作通用領域模型。

### 4.3 為什麼成績不能用 `CHAR(20)`

`input()` 回傳的是 Python 字串，所以原程式把 `"60"` 寫進 `CHAR(20)`
的確能跑。然而「輸入時是文字」不等於「資料的本質是文字」。

具體比較：

| 值                    | 存成文字時                       | 存成數字時                        |
| --------------------- | -------------------------------- | --------------------------------- |
| `"100"` 與 `"9"` 排序 | 可能依字典順序判斷 `"100" < "9"` | 正確判斷 `100 > 9`                |
| `"abc"`               | 可以寫入                         | 型別轉換或資料庫約束會拒絕        |
| 平均值                | Python 還要逐筆 `float()`        | MySQL 可直接 `AVG()`              |
| 合法範圍              | 欄位本身不知道 0～100            | `CHECK (score BETWEEN 0 AND 100)` |

本教材的分數都是整數，`TINYINT UNSIGNED` 可存 0～255，再用 `CHECK` 把業務範圍縮到 0～100。若未來允許 87.5 分，應改成
`DECIMAL(5,2)`，不要改成 `FLOAT` 或文字。

### 4.4 單一大表的適用範圍

這堂課只處理「每名學生目前一組固定五科成績」，一張扁平表足以示範基本操作，也能降低初學負擔。

但它隱含以下假設：

- 永遠只有一次考試。
- 科目永遠固定為五科。
- 每名學生每科只會有一筆成績。

如果要支援期中、期末、多學期或動態科目，就應考慮拆成：

```text
students ──< scores >── subjects
               │
               v
             exams
```

- `students`：學生身分，一名學生只存一次。
- `subjects`：科目定義，例如英文、數學。
- `exams`：考試場次，例如 2026 上學期期中考。
- `scores`：哪名學生在哪次考試的哪一科得到幾分。

本堂為了控制教學範圍，先使用單表。這個設計不處理完整校務系統的需求。

### 5.4 建立教學版 `students` 表

仍以 root 身分執行以下 DDL：

```sql
USE mydatabase;

CREATE TABLE IF NOT EXISTS students (
    id INT UNSIGNED NOT NULL AUTO_INCREMENT,
    student_no VARCHAR(20) NOT NULL,
    name VARCHAR(100) NOT NULL,
    gender_code CHAR(1) NULL,
    chinese TINYINT UNSIGNED NOT NULL,
    english TINYINT UNSIGNED NOT NULL,
    math TINYINT UNSIGNED NOT NULL,
    social_science TINYINT UNSIGNED NOT NULL,
    science TINYINT UNSIGNED NOT NULL,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
        ON UPDATE CURRENT_TIMESTAMP,

    CONSTRAINT pk_students PRIMARY KEY (id),
    CONSTRAINT uq_students_student_no UNIQUE (student_no),
    CONSTRAINT chk_students_gender_code
        CHECK (gender_code IS NULL OR gender_code IN ('M', 'F')),
    CONSTRAINT chk_students_chinese
        CHECK (chinese BETWEEN 0 AND 100),
    CONSTRAINT chk_students_english
        CHECK (english BETWEEN 0 AND 100),
    CONSTRAINT chk_students_math
        CHECK (math BETWEEN 0 AND 100),
    CONSTRAINT chk_students_social_science
        CHECK (social_science BETWEEN 0 AND 100),
    CONSTRAINT chk_students_science
        CHECK (science BETWEEN 0 AND 100)
) ENGINE = InnoDB
  DEFAULT CHARACTER SET = utf8mb4
  COLLATE = utf8mb4_0900_ai_ci;
```

`IF NOT EXISTS` 只會避免「表已存在」錯誤；它不會把原本全是 `CHAR(20)` 的舊表自動升級成新結構。如果
`SHOW CREATE TABLE students` 顯示的是舊 schema，先確認這是可丟棄的練習資料，再由 root 明確執行
`DROP TABLE students`，然後重跑上面的 `CREATE TABLE`。若資料需要保留，就應寫 `ALTER TABLE` 或資料遷移，不能直接刪表。

每個欄位的角色：

- `id`：資料庫內部流水號，由 MySQL 的 `AUTO_INCREMENT` 產生。
- `student_no`：業務上的學生識別碼。名字可能重複，所以更新與查詢應以它為準。
- `name`：學生顯示名稱，長度可變，所以用 `VARCHAR`。
- `gender_code`：為了對照原 CSV 暫留的一字元教材代碼，可為空。
- 五科欄位：保存 0～100 的整數分數。
- `created_at`／`updated_at`：記錄建立與最後修改時間，方便追查資料變動。

#### `CONSTRAINT` 約束的讀法

這組 `CONSTRAINT`
的目的是把資料規則交給 MySQL 執行。它們不是像 Python 或 JavaScript 一樣由上往下執行的流程；MySQL 建表時會登記所有約束，之後每次
`INSERT` 或 `UPDATE` 都必須通過。

基本格式是：

```sql
CONSTRAINT 約束名稱 約束規則
```

本表使用三種名稱前綴：

| 前綴  | 完整名稱    | 用途             |
| ----- | ----------- | ---------------- |
| `pk`  | Primary Key | 指定主鍵         |
| `uq`  | Unique      | 限制值不可重複   |
| `chk` | Check       | 檢查條件是否成立 |

名稱本身不負責驗證；真正的規則是後面的 `PRIMARY KEY`、`UNIQUE` 或
`CHECK`。清楚命名可以讓錯誤訊息與 schema 比較容易追查。MySQL 的主鍵索引名稱固定是 `PRIMARY`，所以 `SHOW INDEX`
不會把它顯示成 `pk_students`。

#### 主鍵與唯一學號

```sql
CONSTRAINT pk_students PRIMARY KEY (id),
CONSTRAINT uq_students_student_no UNIQUE (student_no)
```

`PRIMARY KEY (id)` 把 `id` 設為每列資料的主要識別值。`id` 不能是 `NULL`，也不能重複；一張表只能有一組主鍵。本表的 `id`
還有 `AUTO_INCREMENT`，因此通常由 MySQL 自動產生，Python 不必自己指定。

`UNIQUE (student_no)` 要求每名學生使用不同的學號。`id` 是資料庫內部識別值，`student_no`
則是業務上的唯一學號，兩者不能互相取代。

具體分支如下：

| 目前資料                   | 新資料              | 條件結果           | 最後路徑           |
| -------------------------- | ------------------- | ------------------ | ------------------ |
| 已有 `student_no = 'S001'` | 寫入 `S002`         | 沒有重複           | 允許繼續寫入       |
| 已有 `student_no = 'S001'` | 再寫入 `S001`       | 違反 `UNIQUE`      | MySQL 拒絕這列資料 |
| 已有 `id = 1`              | 明確再寫入 `id = 1` | 違反 `PRIMARY KEY` | MySQL 拒絕這列資料 |

#### `gender_code` 的允許值

```sql
CONSTRAINT chk_students_gender_code
    CHECK (gender_code IS NULL OR gender_code IN ('M', 'F'))
```

把 `IN` 展開後，相當於：

```sql
CHECK (
    gender_code IS NULL
    OR gender_code = 'M'
    OR gender_code = 'F'
)
```

JavaScript 可類比為：

```javascript
genderCode === null || genderCode === "M" || genderCode === "F";
```

各輸入值會走以下分支：

| 輸入   | `IS NULL` | `IN ('M', 'F')` | 最後路徑       |
| ------ | --------: | --------------: | -------------- |
| `NULL` |    `TRUE` |  不影響整體結果 | 通過           |
| `'M'`  |   `FALSE` |          `TRUE` | 通過           |
| `'F'`  |   `FALSE` |          `TRUE` | 通過           |
| `'X'`  |   `FALSE` |         `FALSE` | MySQL 拒絕寫入 |

SQL 判斷空值必須使用 `IS NULL`，不能寫成 `gender_code = NULL`。另外，本表的 `utf8mb4_0900_ai_ci`
排序規則不區分大小寫，因此資料庫比較時，`'m'` 可能被視為等同於 `'M'`。第 7.3 節的 Python 程式會先呼叫
`.upper()`，所以教材流程仍會保存大寫代碼；這條 `CHECK` 本身則沒有嚴格限制大小寫。

#### 五科分數的範圍

以國文為例：

```sql
CONSTRAINT chk_students_chinese
    CHECK (chinese BETWEEN 0 AND 100)
```

`BETWEEN` 包含上下界，完整形式是：

```sql
CHECK (chinese >= 0 AND chinese <= 100)
```

JavaScript 可類比為：

```javascript
chinese >= 0 && chinese <= 100;
```

具體分支如下：

|  分數 |  `>= 0` | `<= 100` | 最後路徑 |
| ----: | ------: | -------: | -------- |
|   `0` |  `TRUE` |   `TRUE` | 通過     |
|  `60` |  `TRUE` |   `TRUE` | 通過     |
| `100` |  `TRUE` |   `TRUE` | 通過     |
|  `-1` | `FALSE` |   `TRUE` | 拒絕     |
| `101` |  `TRUE` |  `FALSE` | 拒絕     |

英文、數學、社會與自然的四條 `CHECK` 使用相同規則，只是檢查不同欄位。分開命名後，錯誤訊息才能指出是哪一科違反限制。

完整欄位定義還包含 `TINYINT UNSIGNED NOT NULL`。三層規則分工如下：

- `TINYINT UNSIGNED`：限制為非負的小整數型別，可表示 0～255。
- `NOT NULL`：不允許缺少分數。
- `CHECK (... BETWEEN 0 AND 100)`：把教材允許的業務範圍縮到 0～100。

`CHECK` 條件得到 `FALSE` 時才違反約束；若結果是由 `NULL` 產生的 `UNKNOWN`，MySQL 仍視為通過。因此分數欄位還需要
`NOT NULL`，不能只依靠 `CHECK`。

#### 一筆資料的完整檢查路徑

假設要寫入：

```text
student_no = S001
gender_code = M
chinese = 60
english = 72
math = 32
social_science = 52
science = 86
```

MySQL 會確認 `id` 沒有重複、`S001` 尚未存在、`M`
符合教材代碼，而且五科都介於 0～100。所有約束都通過後，這列資料才能寫入。

如果把 `math` 改成 132，`132 BETWEEN 0 AND 100` 會得到 `FALSE`，因此 `chk_students_math` 失敗，MySQL 拒絕這列資料。MySQL
8.4 會在 `INSERT`、`UPDATE`、`REPLACE` 與資料匯入時執行 `CHECK`；條件為 `FALSE` 就產生約束錯誤。詳見
[MySQL 8.4：CREATE TABLE](https://dev.mysql.com/doc/refman/8.4/en/create-table.html) 與
[MySQL 8.4：CHECK Constraints](https://dev.mysql.com/doc/refman/8.4/en/create-table-check-constraints.html)。

白話來說，這些約束保證每列有不重複的 `id`、每個學號只出現一次、`gender_code`
符合教材允許的值，而且五科分數都是 0～100 的整數。這些規則只保護 `students`
表內的資料，沒有處理學生與其他資料表之間的關係。

建完後驗證：

```sql
SHOW CREATE TABLE students;
DESCRIBE students;
SELECT COUNT(*) AS student_count FROM students;
```

### 6.2 建立不含明文密碼的共用連線 cell

```python
from getpass import getpass

import MySQLdb
import MySQLdb.cursors

DB_PASSWORD = getpass("grade_app password: ")

DB_CONFIG = {
    "host": "127.0.0.1",
    "port": 3306,
    "user": "grade_app",
    "password": DB_PASSWORD,
    "database": "mydatabase",
    "charset": "utf8mb4",
    "cursorclass": MySQLdb.cursors.DictCursor,
}


def open_db():
    return MySQLdb.connect(**DB_CONFIG)
```

依執行順序解釋：

1. `getpass` 是從標準函式庫匯入的函式；它讓使用者輸入密碼時不把內容顯示或保存成 notebook 原始碼。
2. `DB_PASSWORD` 保存這次執行時輸入的密碼，下一步會放入連線設定。
3. `DB_CONFIG` 保存主機、連接埠、帳號、密碼、資料庫、字元集與 cursor 類型；`open_db()` 會使用它。
4. `DictCursor` 讓查詢結果成為以欄位名稱取值的字典。
5. `open_db()` 每次被呼叫都建立一條新的 MySQL 連線；呼叫者仍必須在最後關閉連線。

連線測試：

```python
db = open_db()
cursor = db.cursor()

try:
    cursor.execute("SELECT VERSION() AS mysql_version")
    server_info = cursor.fetchone()
    print(server_info["mysql_version"])
finally:
    cursor.close()
    db.close()
```

- `db` 保存剛建立的 MySQL connection。
- `cursor` 保存由 `db` 建立的操作游標；下一行由它送出 SQL。
- `server_info` 保存 `fetchone()` 取得的一列字典；這裡只有 `mysql_version` 一個欄位。
- `finally` 不論查詢成功或失敗都會執行，因此 cursor 與 connection 不會遺留。

### 6.3 外部修改 notebook 時，先處理瀏覽器與磁碟的雙重狀態

Jupyter 開啟 `.ipynb` 後，同一份 notebook 會同時存在兩個容易混淆的狀態：

- **瀏覽器中的編輯狀態**：畫面上目前看得到、按下執行時真正使用的 cell 原始碼。
- **磁碟上的 `.ipynb` 檔案**：Jupyter 最近一次儲存，或外部工具直接修改的 JSON 檔案。

外部工具修改磁碟檔案後，已開啟的 Jupyter 頁面不會可靠地自動載入新內容。Jupyter 之後自動儲存時，還可能把瀏覽器中的舊 cell 寫回磁碟，覆蓋外部修改。只執行
**Restart Kernel** 也無法解決，因為它只重啟 Python 執行環境，不會重新載入 cell 原始碼。

判斷時以 traceback 顯示的程式碼為準。例如畫面上宣稱已改成：

```python
CSV_PATH = Path("2-exam_score.csv")
```

但新產生的 traceback 仍顯示：

```python
PROJECT_ROOT = Path.cwd()
LESSON_DIR = PROJECT_ROOT / "exercise" / "tibame" / "2-成績查詢系統"
```

這代表剛才執行的仍是瀏覽器中的舊 cell，不是修改後的磁碟版本。這時不要繼續重跑，也不要只重啟 kernel，應依序處理：

1. 停止重複執行該 cell。
2. 直接檢查瀏覽器中該 cell 的原始碼。
3. 若要保留外部修改，關閉舊頁面時不要讓舊內容再次覆蓋磁碟；或者直接在目前開啟的 Jupyter cell 中修改。
4. 儲存 notebook，確認 cell 顯示的是新版程式。
5. 先執行最小檢查，再執行有資料庫副作用的完整 cell。

先確認實際執行的是哪一份 cell，再檢查 Python 路徑。如果 traceback 仍列出已刪除的程式碼，先解決 notebook 狀態不同步，再檢查其他假設。

## 7. 依序完成教學功能

### 7.1 新增兩名手動輸入學生

```python
student_rows = [
    ("S001", "isaac", "M", 60, 72, 32, 52, 86),
    ("S002", "amy", "F", 50, 22, 80, 15, 93),
]

insert_sql = """
    INSERT INTO students (
        student_no,
        name,
        gender_code,
        chinese,
        english,
        math,
        social_science,
        science
    )
    VALUES (%s, %s, %s, %s, %s, %s, %s, %s)
"""

db = open_db()
cursor = db.cursor()

try:
    cursor.executemany(insert_sql, student_rows)
    db.commit()
except MySQLdb.Error as error:
    db.rollback()
    raise RuntimeError("新增學生失敗，這批資料已回滾") from error
finally:
    cursor.close()
    db.close()
```

第一次出現的變數：

- `student_rows`：保存兩列待新增資料；值來自教材指定的 Isaac 與 Amy 成績，下一步交給 `executemany()`。
- `insert_sql`：保存一份參數化 `INSERT`；八個 `%s` 依序對應每個 tuple 的八個值。
- `error`：只有 `MySQLdb` 操作失敗時才會建立，保存原始資料庫例外；`raise ... from error` 保留可排錯的原因鏈。

成功分支會一次寫入兩列再 `commit()`。例如第二列數學 80 通過所有約束，兩列一起生效。失敗分支會整批
`rollback()`；例如把 80 改成 180，Amy 觸發 `CHECK`，Isaac 也不會留下半套資料。

原 notebook 的互動迴圈有三種輸入結果：

```python
while True:
    # 前面省略本輪的姓名與成績輸入
    again = input("continue(y/n)? ")

    if again[0].lower() == "n":
        break
```

- 輸入 `y`：`again[0]` 是 `"y"`，條件為 `False`，進入下一輪。
- 輸入 `n`：條件為 `True`，執行 `break`。
- 直接按 Enter：`again` 是空字串，沒有索引 0，程式得到 `IndexError`。

若保留互動輸入，應先用 `again = input(...).strip().lower()` 正規化，再明確接受 `y` 或 `n`；成績也要用 `int()`
轉型並檢查 0～100。

### 7.3 補齊並匯入 CSV

目前的 `2-exam_score.csv`
包含 Loe、Judy、Lily、Evan、Joyce、Yoshi、Amber、Alex、Sophia 共九筆資料。Sophia 匯入時的英文成績是 70，後續第 7.4 節會更新為 99。

CSV 使用 UTF-8，欄位如下：

```csv
student_no,name,gender_code,chinese,english,math,social_science,science
S003,loe,M,70,48,69,50,66
S004,judy,F,89,90,59,28,39
S005,lily,F,37,43,67,34,43
S006,evan,M,12,57,97,100,100
S007,joyce,F,58,48,47,98,37
S008,yoshi,M,58,49,79,38,20

```

不要用 `line.split(",")` 解析正式 CSV。只要姓名含逗號、引號或換行，手動切割就會錯；Python 標準函式庫的 `csv.DictReader`
會依 CSV 規則處理。

路徑也要先釐清。在 Jupyter 中，無法用可靠的 `__file__` 取得 notebook 路徑。`open("2-exam_score.csv")`
會以 kernel 目前工作目錄為基準，這個目錄可能和 `.ipynb` 所在目錄不同。

本練習從 notebook 所在目錄啟動 Jupyter，因此 CSV 可以使用相對路徑：

先用獨立 cell 做最小路徑檢查：

```python
from pathlib import Path

CSV_PATH = Path("2-exam_score.csv")

print("kernel 工作目錄：", Path.cwd())
print("CSV 完整路徑：", CSV_PATH.resolve())
print("CSV 是否存在：", CSV_PATH.is_file())
```

只有 `CSV 是否存在` 顯示 `True`，才繼續解析 CSV 與寫入資料庫。這樣可以分開定位「找不到檔案」與「MySQL 寫入失敗」。

```python
import csv
from pathlib import Path

CSV_PATH = Path("2-exam_score.csv")

if not CSV_PATH.is_file():
    raise FileNotFoundError(f"找不到 CSV：{CSV_PATH}")

csv_rows = []

with CSV_PATH.open(encoding="utf-8-sig", newline="") as csv_file:
    reader = csv.DictReader(csv_file)

    for line_number, row in enumerate(reader, start=2):
        scores = [
            int(row["chinese"]),
            int(row["english"]),
            int(row["math"]),
            int(row["social_science"]),
            int(row["science"]),
        ]

        invalid_score_found = False

        for score in scores:
            if score < 0 or score > 100:
                invalid_score_found = True
                break

        if invalid_score_found:
            raise ValueError(f"CSV 第 {line_number} 列含有 0～100 以外的成績")

        csv_rows.append(
            (
                row["student_no"].strip(),
                row["name"].strip(),
                row["gender_code"].strip().upper() or None,
                *scores,
            )
        )

insert_sql = """
    INSERT IGNORE INTO students (
        student_no,
        name,
        gender_code,
        chinese,
        english,
        math,
        social_science,
        science
    )
    VALUES (%s, %s, %s, %s, %s, %s, %s, %s)
"""

db = open_db()
cursor = db.cursor()

try:
    cursor.executemany(insert_sql, csv_rows)
    db.commit()
except MySQLdb.Error as error:
    db.rollback()
    raise RuntimeError("CSV 匯入失敗，整批資料已回滾") from error
finally:
    cursor.close()
    db.close()
```

新變數依執行順序說明：

- `CSV_PATH`：保存相對於 kernel 目前工作目錄的 CSV 路徑，用於存在檢查與開檔；這裡假設工作目錄就是 notebook 所在目錄。
- `csv_rows`：一開始是空 list，驗證通過的每列資料會加入，最後交給 `executemany()`。
- `csv_file`：`with` 開啟的檔案物件，離開區塊後自動關閉。
- `reader`：`DictReader` 依標題列把每列轉成字典。
- `line_number`：保存目前 CSV 行號，從 2 開始，錯誤訊息可直接指向原檔。
- `row`：保存目前一列原始文字資料。
- `scores`：把目前列的五科文字轉成五個 `int`，下一個迴圈檢查其範圍。
- `invalid_score_found`：一開始是 `False`；只要找到不合法分數就改成 `True`，並由下一個 `if` 決定是否停止匯入。
- `score`：範圍檢查迴圈當下的一個分數，來源依序為 `scores`。
- `insert_sql`：在這個範例中重新完整定義，最後讓 `executemany()` 把所有 `csv_rows` 套入同一份 SQL。

這裡使用 `INSERT IGNORE`，是因為 notebook cell 很容易被重複執行：

- 第一次執行時，S003～S011 尚不存在，因此新增九列。
- 再次執行時，`student_no` 的唯一約束發現 S003～S011 已存在，因此略過重複列，不再產生 `Duplicate entry`。

如果改用一般的 `INSERT`，第一次匯入成功後再次執行，會得到類似以下錯誤：

```text
IntegrityError: (1062, "Duplicate entry 'S003' for key 'students.uq_students_student_no'")
```

這不是 CSV 讀取失敗，也不是 `db.close()` 出錯。traceback 最下方雖然可能指向 `finally` 區塊附近，但真正的原始錯誤發生在
`cursor.executemany()` 寫入重複學號時。閱讀 traceback 要先找最早的 `IntegrityError`，再看最後包裝出的 `RuntimeError`。

`INSERT IGNORE`
適合這個可重跑的固定教材資料。正式系統若需要用 CSV 新值覆蓋舊資料，應改用明確的 upsert；若資料不合法必須立刻失敗，也不應用
`IGNORE` 隱藏警告。

這裡的 `*scores` 是 Python 的 iterable unpacking。展開後，tuple 最後五個位置依序是
`scores[0]`、`scores[1]`、`scores[2]`、`scores[3]`、`scores[4]`。這是 Python 語法，不是 SQL 語法。JavaScript 中可類比為陣列的 spread：`[...scores]`。

### 7.4 把 Sophia 英文改成 99

```python
update_sql = "UPDATE students SET english = %s WHERE student_no = %s"
update_values = (99, "S011")

db = open_db()
cursor = db.cursor()

try:
    cursor.execute(update_sql, update_values)
    affected_rows = cursor.rowcount

    cursor.execute(
        "SELECT english FROM students WHERE student_no = %s",
        ("S011",),
    )
    sophia = cursor.fetchone()

    if sophia is None:
        db.rollback()
        raise RuntimeError("找不到學號 S011，沒有任何資料可更新")

    db.commit()
    print(f"實際變更 {affected_rows} 列；目前英文成績為 {sophia['english']}")
except MySQLdb.Error as error:
    db.rollback()
    raise RuntimeError("更新 Sophia 成績失敗") from error
finally:
    cursor.close()
    db.close()
```

- `update_sql` 保存參數化的 `UPDATE`；第一個 `%s` 是新英文成績，第二個 `%s` 是目標學號。
- `update_values` 保存要依序綁定的 `(99, "S011")`。SQL 與值分開傳入，可避免把外部輸入直接拼進 SQL。
- `affected_rows` 保存 `UPDATE` 實際改變的列數，值來自當下的 `cursor.rowcount`；必須在執行下一條 SQL 前先保存。
- `sophia` 保存以唯一學號查回的一列；它用來區分「學生不存在」和「分數本來就是 99」。

分支例子：

- `S011` 存在且英文原本不是 99：通常 `affected_rows == 1`，查回英文 99 後提交。
- `S011` 存在且英文已經是 99：MySQL 預設可能回報 `affected_rows == 0`，但 `sophia`
  仍有資料；這是成功的重跑，不是「學生不存在」。
- `S011` 不存在：`affected_rows == 0` 且 `sophia is None`，程式回滾並指出沒有目標。
- 若使用不唯一的姓名當條件，兩名學生都叫 Sophia：可能一次更新兩列；因此更新條件必須使用唯一的 `student_no`。

### 7.5 交給 MySQL 計算平均

```python
average_sql = """
    SELECT
        ROUND(AVG(chinese), 2) AS chinese_avg,
        ROUND(AVG(english), 2) AS english_avg,
        ROUND(AVG(math), 2) AS math_avg,
        ROUND(AVG(social_science), 2) AS social_science_avg,
        ROUND(AVG(science), 2) AS science_avg
    FROM students
"""

db = open_db()
cursor = db.cursor()

try:
    cursor.execute(average_sql)
    averages = cursor.fetchone()

    if averages["chinese_avg"] is None:
        print("尚無成績")
    else:
        print(averages)
finally:
    cursor.close()
    db.close()
```

- `average_sql` 保存五個聚合運算；每個 `AVG()` 由 MySQL 對整欄計算，`ROUND(..., 2)` 顯示兩位小數。
- `averages` 保存唯一一列統計結果。
- 有資料時，`chinese_avg` 會是數值，進入 `else` 印出結果。
- 空表時，各科 `AVG()` 都是 `NULL`，`DictCursor` 轉成 Python 的 `None`，進入第一個分支顯示「尚無成績」。

## 8. 原 notebook 逐段檢查

| 原寫法                                      | 問題或假設                              | 建議                                                               |
| ------------------------------------------- | --------------------------------------- | ------------------------------------------------------------------ |
| `MySQLdb.connect("localhost", "root", ...)` | 位置參數難讀、使用 root、密碼外洩       | 使用具名參數、低權限帳號、執行時取密碼                             |
| `DROP DATABASE IF EXISTS STUDENTS`          | 刪錯物件，且具有高破壞性                | 建表交給管理步驟；重設時才明確 `DROP TABLE`                        |
| `CHAR(20)` 保存所有值                       | 把姓名、代碼、數字混成同一型別          | 依領域使用 `VARCHAR`、`CHAR(1)`、`TINYINT`                         |
| `DEFAULT CHARSET=utf8`                      | 在 MySQL 8.4 是已棄用的 `utf8mb3` 別名  | 使用 `utf8mb4`                                                     |
| `input()` 後直接入庫                        | 所有輸入仍是文字，沒有範圍驗證          | `strip()`、`int()`、0～100 檢查，DB 再設 `CHECK`                   |
| `except:`                                   | 吞掉程式錯誤、連線錯誤與資料錯誤        | 捕捉 `MySQLdb.Error`，回滾後保留原始例外                           |
| 每列 CSV 都 `commit()`                      | 中途失敗會留下半批資料，速度也較慢      | `executemany()` 後整批 commit                                      |
| `readlines()`                               | 先把整個檔案載入記憶體                  | 直接迭代 `DictReader`                                              |
| `split(",")`                                | 不理解 CSV 的引號與逗號規則             | 使用標準 `csv` 模組                                                |
| `open("2-exam_score.csv")`                  | 假設 kernel 工作目錄等於 notebook 目錄  | 先檢查 `Path.cwd()`，再用 `Path` 明確表示 `CSV_PATH`               |
| 外部修改已開啟的 `.ipynb`                   | 瀏覽器舊 cell 可能自動儲存並覆蓋磁碟    | 以畫面與新 traceback 為準；直接修改 live cell 或關閉後再外部修改   |
| 只做 Restart Kernel                         | 只重啟 Python，不會重新載入 cell 原始碼 | cell 顯示舊程式時必須重新載入或直接修改 cell                       |
| CSV 匯入 cell 使用一般 `INSERT`             | 重跑時唯一學號造成 `Duplicate entry`    | 固定教材資料使用 `INSERT IGNORE`；需覆蓋舊值時使用明確 upsert      |
| `SELECT *` 加 `row[3]`                      | 依賴欄位順序，schema 一改就錯位         | 明列欄位並使用 `DictCursor`                                        |
| 用姓名更新 Sophia                           | 姓名不保證唯一，可能改到多人            | 增加唯一學號並以學號更新                                           |
| Python 逐列算平均                           | 多傳資料、手動轉型、空表會除以零        | 小量或低頻查詢使用 SQL `AVG()`；高頻統計改用快取、彙總表或 replica |
| 最後才 `db.close()`                         | 前面拋例外時可能走不到                  | 在 `finally` 關閉 cursor 與 connection                             |

## 10. 白話重述、假設與範圍

管理者先在 MySQL 建好
`mydatabase.students`，由資料庫限制欄位型別、唯一學號與成績範圍。Python 再用低權限帳號連線，把 SQL 與資料分開傳給
`MySQLdb`。手動資料與 CSV 都先在 Python 驗證，再以一個交易批次寫入。查詢時明列欄位並用名稱取值；修改時用唯一學號指定一名學生；本教材的小量、低頻平均值查詢交給 MySQL 的
`AVG()`
計算。正式系統若有大量重複統計請求，則改用快取、彙總表或 replica。任何資料庫錯誤都會回滾並保留原始原因，最後一定關閉資源。

本文的範圍還有以下限制：

- 分數都是 0～100 的整數；若有小數要改用 `DECIMAL`。
- `gender_code` 只是對照原教材的代碼，不是完整的人員資料模型。
- 一名學生只有一組固定五科成績；多次考試或動態科目不在此單表設計範圍。
- 沒有處理登入、畫面、API、多人同時編輯、備份與正式環境部署。
- 遺失 CSV 中 Sophia 更新前的英文分數無法從 notebook 最終輸出還原；本文示例值只是為了補齊教學流程。

學完後，應能不回看前文而說出：每個連線與查詢變數保存什麼、成功與失敗分支各做什麼、為什麼分數必須是數值、為什麼不能用名字更新唯一學生，以及整套流程依賴哪些資料與環境假設。

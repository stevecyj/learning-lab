# 認識數字類型 (Numeric Data Types)

這一節介紹 MySQL 的三種數字類型：整數（含 `UNSIGNED`）、浮點數（`DOUBLE`）與可指定精度的定點數（`DECIMAL`），並比較它們的儲存方式、數值範圍與適用場景。

---

## 1. 為什麼要區分數字類型

資料庫中的數值資料有不同需求：編號與數量不需要小數，科學量測容許微小誤差，而交易金額則要求每一位數都完全精確。

型別選錯時，常見問題有三種：

1. 浮點數精度誤差：用 `DOUBLE` 存金額時，二進位浮點運算的近似值會讓帳目加總出現微小偏差。
2. 數值範圍浪費或溢位：主鍵 ID 不會有負數，若使用預設的 `SIGNED` 整數，負數範圍便用不到；若型別範圍太小，例如使用 `TINYINT`，資料增加後則可能溢位。
3. 位數約束不足：未依業務規則限制整數與小數位數，可能讓不符合格式的資料進入資料庫，或在超出型別範圍時寫入失敗。

接下來會比較整數、`DOUBLE` 與 `DECIMAL`，說明定義欄位時該如何選擇數值範圍與精度。

---

## 2. 核心概念

### 概念一：整數與無符號屬性 (Integer & `UNSIGNED`)

`INT`、`TINYINT` 等整數型別用來儲存不含小數的數值。若資料不可能是負數，可以加上 `UNSIGNED`；在 MySQL Workbench 中，這個選項縮寫為 `UN`。

整數型別以固定位元組儲存。相較於用浮點數或字串保存整數，它能節省空間，也更適合建立索引。`UNSIGNED` 會把原本的負數範圍改成正數範圍，因此正整數上限約為原本的兩倍。例如，`TINYINT` 的有符號範圍是 `-128 ~ 127`，無符號範圍則是 `0 ~ 255`。

主鍵 ID、流水號、年齡與商品數量通常適合使用無符號整數。溫度、帳戶增減量或座標位移可能是負數，不應加上 `UNSIGNED`。

### 概念二：浮點數 (`DOUBLE` / Floating-Point)

`DOUBLE` 用來儲存帶有小數的數值。它在固定空間內以類似科學記號的方式表示數字，因此能涵蓋很大或很小的數值，也能使用 CPU 的浮點運算。不過，許多十進位小數無法用二進位精確表示，儲存的是近似值。

感測器數據、概略百分比與科學數據通常容許微小誤差，適合使用 `DOUBLE`。訂單金額、帳戶餘額與稅額需要精確計算，不適合使用 `DOUBLE`。

### 概念三：可指定精度的定點數 (`DECIMAL(M, D)`)

`DECIMAL(M, D)` 可以指定總位數與小數位數，並精確儲存十進位數值：

- `M`（Precision）是總位數，也就是整數位數加上小數位數。例如，`DECIMAL(8, 2)` 最多有 8 位數。
- `D`（Scale）是小數位數。`DECIMAL(8, 2)` 會保留 2 位小數。
- 整數最多有 `M - D` 位。`DECIMAL(8, 2)` 的整數部分最多有 `8 - 2 = 6` 位。

`DECIMAL` 不會產生二進位浮點數的近似誤差，也能限制欄位可接受的整數與小數位數，因此適合商品單價、結算金額、匯率與稅額。不含小數的資料應使用整數型別；若數值範圍很廣而且容許誤差，通常使用浮點數較合適。

## 3. 圖解

### 1. 有符號 (`SIGNED`) vs 無符號 (`UNSIGNED`) 空間分配

整數欄位的二進位總容量固定。以 8 位元的 `TINYINT`（共 256 個可能值）為例：

```
預設 SIGNED (有符號):
[-128 ------------------- 0 ------------------- 127]
 <──── 負數佔一半 ────>     <──── 正數佔一半 ────>
 (用於主鍵 ID 時，負數範圍無法利用)

啟用 UNSIGNED (無符號):
[0 -------------------------------------------- 255]
 <────────────── 全部容量提供給正數 ──────────────>
 (正數上限翻倍，不浪費編號容量)
```

---

### 2. `DECIMAL(M, D)` 的位數拆解

以 `DECIMAL(8, 2)` 為例，總位數 `M = 8`，小數位數 `D = 2`：

```
                    ┌───────────────────────────────┐
                    │     DECIMAL(8, 2) 總位數: 8    │
                    └───────────────┬───────────────┘
                                    │
            ┌───────────────────────┴───────────────────────┐
            ▼                                               ▼
┌───────────────────────┐                       ┌───────────────────────┐
│  整數部分 (M - D = 6)  │       [ 小數點 . ]     │    小數部分 (D = 2)   │
│     9 9 9 9 9 9       │           .           │          9 9          │
└───────────────────────┘                       └───────────────────────┘
  (最大正值: 999999.99，整數最多 6 位，小數保留 2 位)
```

---

### 3. `DOUBLE` (浮點數) vs `DECIMAL` (定點數) 儲存機制

```
儲存數值 0.1:

[ DOUBLE (二進位近似值) ]
二進位無法精確表示 0.1 ──► 0.0001100110011... ──► 內部值: 0.10000000000000000555...
(多次運算容易累積誤差)

[ DECIMAL(4, 2) (十進位精準儲存) ]
十進位數值對齊儲存 ──► 整數: 00, 小數: 10 ──► 內部值: 0.10
(運算結果精準，無二進位轉換誤差)
```

## 4. 實務注意事項

### 基本設定

1. Workbench 的 `UN` 代表 `UNSIGNED`：在 MySQL Workbench 的欄位設定中，勾選 `UN` 即代表無符號整數。
2. `DECIMAL(M, D)` 的 `M` 是總位數，不是整數位數：`DECIMAL(8, 2)` 的整數部分最多有 `8 - 2 = 6` 位，最大值是 `999999.99`。
3. 整數欄位不會自動保留小數：將小數寫入 `INT` 欄位時，MySQL 會將它轉成整數，處理結果也會受 SQL Mode 影響；資料庫不會自行把欄位改成浮點數。

### 資料表設計

1. 金額欄位使用 `DECIMAL` 或最小整數單位：涉及財務計算的金額應使用 `DECIMAL`，也可以換算成最小單位，例如「分」或 cents，再用 `BIGINT` 或 `INT` 儲存，以免累積浮點誤差（*延伸知識*）。
2. 主鍵與外鍵的型別及符號必須一致：若主表的主鍵是 `INT UNSIGNED`，關聯表的外鍵也必須是 `INT UNSIGNED`，否則無法建立外鍵約束（*延伸知識*）。
3. 預留業務增長空間：宣告 `DECIMAL(M, D)` 時，要估算資料未來可能到達的最大值。例如，`DECIMAL(8, 2)` 的上限是 `999,999.99`；若金額超過上限，寫入時會出現 `Numeric value out of range` 錯誤。

| 分類 | 具體內容 | 通用程式設計對應觀念 |
| :--- | :--- | :--- |
| MySQL 語法與工具 | Workbench 勾選 `UN`<br>`INT UNSIGNED`<br>`DECIMAL(M, D)` | 資料定義語言（DDL）中的數值型別與符號約束宣告。 |

| 通用觀念 | IEEE 754 浮點數精度限制 | JavaScript 的 `Number`、Python 的 `float` 與 MySQL `DOUBLE` 都使用二進位浮點數，因此可能出現小數精度誤差。 |

| 通用觀念 | Schema 層級型別約束 | 由資料庫限制資料格式與範圍，避免不合規格的資料寫入。 |

## 6. 型別取捨

### 1. `INT (SIGNED)` vs `INT UNSIGNED`

| 比較維度 | `INT` (預設有符號) | `INT UNSIGNED` (無符號) |
| :--- | :--- | :--- |
| **數值範圍** | `-2,147,483,648 ~ 2,147,483,647` | `0 ~ 4,294,967,295` |
| **正數容量** | 約 21.4 億 | 約 42.9 億（容量加倍） |
| **負數支援** | 支援 | 不支援（寫入負數會報錯或警告） |
| **適用場景** | 溫度、差額、盈虧、座標位移 | 主鍵 ID、計數器、庫存、年齡 |
| **選錯後果** | 用於流水號 ID 時，浪費一半（約 21 億）的可用編號 | 用於可能出現負數的欄位時，會發生溢位或寫入失敗 |

---

### 2. `DOUBLE` (浮點數) vs `DECIMAL(M, D)` (定點數)

| 比較維度 | `DOUBLE` (浮點數) | `DECIMAL(M, D)` (自訂精準度定點數) |
| :--- | :--- | :--- |
| **精確度** | 近似值（不可自訂小數位數，底層二進位儲存） | 絕對精確（由開發者自訂總位數與小數位數） |
| **運算效能** | 高（使用 CPU 硬體浮點運算） | 較低（由資料庫軟體層模擬十進位運算） |
| **儲存空間** | 固定 8 位元組 | 依 `M` 與 `D` 長度動態分配位元組（*延伸知識*） |
| **適用場景** | 科學計算、物理量測、地理座標（概略） | 貨幣金額、交易結算、發票稅額、會計帳目 |
| **選錯後果** | 用於財務計算會累積四捨五入誤差，導致帳目對不齊 | 用於大量科學計算時，運算耗時與儲存空間增加 |

## 7. 常見誤解

### 誤解一：`DECIMAL(8, 2)` 的整數部分有 8 位，小數部分有 2 位

`M`（8）代表總位數。整數部分最多有 `M - D = 8 - 2 = 6` 位，因此最大值是 `999,999.99`。若輸入 `1234567.89`，寫入時會超出範圍。

### 誤解二：金額用 `DOUBLE` 計算，顯示時再四捨五入即可

浮點數經過多次運算後可能累積微小誤差，導致明細加總與總額不符。例如，二進位浮點運算中的 `0.1 + 0.2` 可能不會精確等於 `0.3`。顯示時四捨五入只會隱藏誤差，不會修正資料與計算結果。

### 誤解三：主鍵 ID 使用預設的 `INT` 就好，不必設定 `UNSIGNED`

主鍵 ID 通常從 1 開始遞增，不會是負數。預設 `INT` 的正整數上限約為 21 億；改用 `UNSIGNED` 後，相同空間可以提供約 43 億個非負整數。

### 誤解四：向 `INT` 欄位寫入 `99.8`，資料庫會自動把欄位改成浮點數

MySQL 欄位建立後，型別不會因為輸入值而改變。向 `INT` 欄位寫入小數時，MySQL 會將數值轉成整數，處理結果也會受 SQL Mode 影響；欄位定義仍然是 `INT`。

1. 字串資料類型 (`CHAR` vs `VARCHAR`)：固定長度與可變長度字串在儲存空間、檢索效能與字元編碼上的差異。

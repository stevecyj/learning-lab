# 9-1 認識 SQL

來源：`9-1-認識SQL.vtt`

老師開頭說「主題八 sql」，檔名卻是第 9 章。這份筆記跟檔名走。本堂沒有教任何一條可執行的查詢，先弄清楚 SQL 是什麼、為什麼有標準、廠商為什麼又各寫一套。

---

## 1. 這堂課真正要解決的問題

關聯式資料庫裡的資料要能被存取，需要一套專門給這種資料庫用的語言。沒有它，你只能對著各家系統各講各的話。

這套語言叫 SQL（Structured Query Language，結構化查詢語言）。1970 年 IBM 做出來，同一年關聯式資料庫模型也被提出。兩者是一起出現的。

各家資料庫管理系統若各寫各的，這套語法很難繼續被大家採用。ANSI、ISO 先後為它訂標準。有標準，後來的發展才有人跟。

標準訂了，廠商仍不一定百分之百照做。老師的估法是：九成以上會遵循；對標準語法，各廠商還會修改或擴充。擴充常用在函式（function）和預存程序（stored procedure）。同一段程式在不同系統上有時不相容，機會比較低。

你寫的可能是大家大致共通的 SQL，也可能是某一家資料庫自己加的那一層。看起來都像 SQL。換系統時，後者較容易卡住。

---

## 2. 核心概念

### 概念 1：SQL 是給關聯式資料庫用的存取語言

它是什麼：一套用來存取關聯式資料庫的語法。全名 Structured Query Language，中文叫結構化查詢語言。

為什麼存在：關聯式模型把資料放進表與關聯裡，需要對應的存取方式。老師把它放在 1970 年，IBM 研發 SQL，同一年關聯式資料庫模型也被提出。

解決什麼問題：讓人用同一類語法去讀、寫關聯式資料。每套系統不必自創一套完全不同的語言。

何時使用：目標是關聯式資料庫時。

何時不適合：逐字稿沒講非關聯式系統。本堂證據到不了「任何資料庫都講 SQL」。

### 概念 2：SQL 語法不區分大小寫

它是什麼：關鍵字怎麼大小寫，系統都當成同一套語法。老師說不管哪一個資料庫管理系統都是如此。

為什麼存在：課堂只陳述這件事，沒解釋歷史原因。`SELECT`、`select`、`Select` 因此不必被當成三種語言。

解決什麼問題：寫的人不用為了大小寫準備多套指令。讀的人也不用把大小寫差當成語法差。

何時使用：寫一般 SQL 關鍵字時，可依團隊習慣選一種大小寫，語意不會因此改變。

何時不適合：課堂把範圍講成「SQL 語法」在各 DBMS 都不區分大小寫。表名、欄名、字串內容是否也一律如此，本堂沒講。

**延伸知識：** 關鍵字通常不區分大小寫；資料庫物件名稱（尤其 Linux 上的表名）有時會區分。本堂沒有這個區分。練習時先跟老師的說法走，語法本身不靠大小寫來分辨。

### 概念 3：標準讓這套語法能被繼續採用

它是什麼：ANSI、ISO 為 SQL 訂定的共同規格。

為什麼存在：這套語法受歡迎，需要一個大家能遵循的版本，發展才接得下去。老師的因果是：有標準可循 → 大家較願意採用 → 對後續發展較有利。

解決什麼問題：避免各家各寫一套、學過的語法無法延續。

何時使用：判斷一段寫法能不能在別套系統跑時，先問它是不是標準語法。

何時不適合：標準沒有涵蓋各廠商後來加的函式、預存程序寫法。那些不在「有標準就保證能搬」的範圍。

### 概念 4：廠商會修改、擴充標準，因此不完全相容

它是什麼：即使有標準，廠商仍可能不完全遵循；對標準語法也會做一定程度的修改或擴充。老師說大體上九成以上會遵循，不相容「難免」，機會較低。

為什麼存在：各家系統要在標準之上提供自己的能力。課堂舉的落點是函式和預存程序。

解決什麼問題：讓廠商能在 SQL 之上加計算、重複呼叫這類能力，不必等標準涵蓋所有需求。

何時使用：確定會一直待在同一套資料庫，而且需要該廠商提供的擴充時。

何時不適合：這段程式可能搬到另一家資料庫時。擴充寫得越深，搬過去越可能卡住。課堂沒給具體不相容的語句，只給了這個風險判斷。

### 概念 5：函式與預存程序是「以 SQL 為基礎的擴展語言」常出現的地方

它是什麼：廠商在 SQL 之上再長出來的語言層，常用來寫函式和預存程序。

- **函式（function）**：學過程式語言的話，概念接近：呼叫時多半做計算或回傳值，寫法上有小括號。
- **預存程序（stored procedure）**：預先寫好、放在資料庫上、給它一個名字，之後供呼叫。目的是重複利用。

為什麼存在：標準 SQL 不夠表達「把一段會重複用的程序放進資料庫再呼叫」。廠商用擴展語言補這塊。

解決什麼問題：計算／回傳（函式），以及把寫好的程序留下來反覆呼叫（預存程序）。

何時使用：同一段資料庫邏輯會被多次呼叫，值得寫好、命名、放進資料庫時。

何時不適合：本堂沒比較「邏輯放資料庫」和「邏輯放應用程式」。推不出預存程序一定比較好。

各廠商這層擴展語言有沒有正式名稱，課堂對照如下：

| 系統 | 課堂怎麼說 |
| --- | --- |
| Oracle DB | 擴展語法叫 PL-SQL |
| Microsoft SQL Server | 擴展語法叫 Transact-SQL |
| MySQL | 確實有自己的語法，但沒有特別名稱；官方文件也沒特別稱呼 |

老師請人去看維基百科「stored procedure」條目，那裡有各廠商擴展語言的名稱。本堂沒有把那一頁的清單讀完。

## 3. Mental Model

把 SQL 想成兩層。標準層各家大致共通；擴充層綁在單一廠商。

```text
要存取關聯式資料庫
        │
        ▼
  SQL（結構化查詢語言）
        │
        ├── 語法層：關鍵字大小寫不當成不同語言
        │
        ├── 標準層：ANSI / ISO
        │         各廠商大體遵循九成以上
        │
        └── 擴充層：以 SQL 為基礎再往外長
                  常用在 函式、預存程序
                  │
                  ├── Oracle     → 有名字：PL-SQL
                  ├── SQL Server → 有名字：Transact-SQL
                  └── MySQL      → 有自己的寫法，官方沒取名
```

1. 關鍵字大小寫不同的同一句，系統仍當同一句。
2. 這句若落在那「九成以上」的標準範圍，換一家系統，通常還認得出來。
3. 這句若用了某家的函式／預存程序寫法，它走的是該廠商的擴展語言。換系統時，不相容的機會才出現。
4. 預存程序的生命週期是：人先寫好 → 放到資料庫 → 取名字 → 之後呼叫。

假設：本堂把「不區分大小寫」講成各 DBMS 的 SQL 語法都如此。字串裡的文字、物件名稱是否同樣處理，不在這個模型裡。

## 4. 專家視角

### 初學者需要知道，但資深工程師通常不會特別思考的內容

- **SQL 是語言。** MySQL、Oracle、SQL Server 是會講這套語言的系統。把「學 MySQL」和「學 SQL」混成一件事，後面會以為換系統等於從零學一種新語言。
- **關鍵字寫成小寫，通常不是語法錯。** 查詢失敗時，先看名稱和資料。
- **MySQL 的擴展語法沒有官方商品名。** 看到 PL-SQL、Transact-SQL 時，MySQL 沒有對等的官方名稱。老師明確說官方文件沒有特別稱呼。

### 即使是資深工程師仍然會注意的內容

- 九成遵循仍留下一成，再加上各廠商對標準語法的修改。把預存程序、函式當核心邏輯時，可攜性押在單一廠商上。
- 課堂點名的是函式與預存程序。一般 `SELECT` 不在這層。審查程式時，先把「標準查詢」和「放在資料庫裡的程序／函式」分開看。
- 不相容機會較低。搬家前仍要在目標系統上跑過。

## 5. 語法 vs 通用知識

### 語言特有知識

- 名稱：SQL / Structured Query Language / 結構化查詢語言。
- 關鍵字大小寫在 SQL 語法裡不當成不同語言。
- Oracle 的擴展叫 PL-SQL，SQL Server 的擴展叫 Transact-SQL；MySQL 有擴展但沒有課堂提到的官方名稱。
- 預存程序是先寫好、放進該資料庫、命名後再呼叫。

### 通用程式設計知識

- **標準與實作會分家。** 語言有規格，各家產品仍會改、會加。規格讓生態能延續，產品差異讓搬家有成本。JavaScript 引擎和編譯器也有同一種分家。
- **重複使用要有「寫好、命名、放在可呼叫的地方」。** 預存程序就是這個想法放到資料庫裡。應用程式裡的函式、模組也是同一類設計，只是存放位置不同。
- **函式偏向計算或回傳；預先寫好的程序偏向被重複呼叫。** 這組分工在多數語言都存在。課堂用「有小括號、多半回傳」來認函式。

## 6. Trade-off

課堂真正拿來對照的，是「跟標準走」和「用廠商擴充」。

| | 儘量只用標準 SQL | 使用廠商擴充（函式、預存程序） |
| --- | --- | --- |
| 差異 | 寫各家大致都認的那九成 | 使用該系統自己長出來的語言層 |
| 好處 | 換系統時較可能直接能跑；學一次能帶到別家 | 能把計算、重複程序放進資料庫，取名後呼叫 |
| 代價 | 課堂點名的函式／預存程序能力用不上 | 換 Oracle、SQL Server、MySQL 時，寫法不一定通 |
| 適合 | 查詢本身、可能換資料庫、要讓語法延續 | 確定留在同一套系統，而且同一段程序會反覆呼叫 |
| 選錯的後果 | 該重複利用的邏輯只能在應用程式裡重寫、重貼 | 以為「都是 SQL」就整包搬走，碰到不相容 |

Oracle／SQL Server 給擴展語言取名，MySQL 不取名。差在辨識成本。有名字時，文件會用那個名字；MySQL 這層只能說「MySQL 自己的語法」。

函式 vs 預存程序：課堂給的是用途差（計算／回傳 vs 寫好放著供呼叫），沒有做成完整的二選一比較。細節設定、效能、權限，逐字稿未涵蓋。

## 7. 常見誤解

1. **SQL 大小寫不同就是不同指令。** 課堂的規則是語法不區分大小寫。把 `SELECT` 和 `select` 當成兩種語言，會找錯 bug。
2. **有 ANSI／ISO 標準，各家寫法就一樣。** 標準是為了延續和採用；老師接著就說廠商不一定完全遵循，還會修改、擴充。九成不是百分之百。
3. **函式和預存程序是同一個東西。** 函式：呼叫時多半計算或回傳，有小括號。預存程序：預先寫好、放在資料庫、命名、供呼叫，為了重複利用。兩者都能被呼叫。課堂仍把它們當成兩種物件。
4. **MySQL 的擴展語言一定也有官方名稱。** 老師對照 Oracle、SQL Server 之後，明確說 MySQL 沒有特別名稱，官方文件也沒特別稱呼。硬套 PL-SQL 或 Transact-SQL 會找錯文件。
5. **會寫某一家的預存程序，就等於會寫通用 SQL。** 預存程序走的是擴充層。那一層過了，不代表換系統後同一份程序還能跑。

## 8. Code Prediction — 請先作答

本堂沒有實機示範。下面三題用課堂規則推，不必真的連上資料庫。請各答：1. 執行結果 2. 為什麼 3. 程式內部發生什麼事

假設已有資料表 `book`，且這三句都只使用課堂所說「九成以上會遵循」的標準查詢長相。

### 題 1

```sql
SELECT title FROM book;
select title from book;
SeLeCt title FrOm book;
```

這三句在同一個資料庫管理系統裡，會不會被當成三種不同語法？

### 題 2

同一句：

```sql
SELECT title FROM book;
```

先在 MySQL 執行，再原封不動拿到 Microsoft SQL Server 執行。請預測兩邊會不會都認這句，以及你依據的是課堂哪一條規則。

### 題 3

某團隊在 SQL Server 寫了一段預存程序（課堂稱該廠商擴展語法為 Transact-SQL）：寫好、放到該資料庫、取名 `list_books`，之後在 SQL Server 上呼叫。現在把「建立這段預存程序」的稿子原封不動貼到 MySQL 執行。

請預測：這份稿子在 MySQL 會走標準 SQL 那一層，還是廠商擴充那一層？接下來可能發生什麼事？

## 10. Coding Challenge

換一個場景：一間租書店，目前用 MySQL。每天打烊要列出「今天租出哪些書」，這段邏輯一週會被櫃台程式呼叫很多次。半年後不排除改用 SQL Server。

**目標**（約 15–20 分鐘）

決定這段「每日租出清單」要寫成哪一種，並寫下你的判斷依據。不必真的連上 MySQL。

**限制**

- 只能用本堂出現過的材料：標準 SQL、函式、預存程序、廠商擴充、不相容風險。
- 不要發明課堂沒教的語法細節（例如預存程序的完整 CREATE 寫法）。用文字說明「放在哪、叫什麼、誰來呼叫」即可。
- 必須同時回答「現在留在 MySQL」和「之後若改 SQL Server」兩種情況。

**完成標準**

- 寫出你選的方案：只放標準查詢、做成函式、或做成預存程序。
- 用課堂定義說明：若選函式，它應該負責什麼；若選預存程序，它的生命週期是哪四步（寫好、放到資料庫、命名、呼叫）。
- 寫出：這個選擇用到的是標準層還是 MySQL 擴充層；改 SQL Server 時，哪一部分較可能還在、哪一部分較可能要重寫。
- 寫出：MySQL 這層擴充有沒有官方名稱，文件該用什麼關鍵字找。

**Stretch**

若櫃台程式和另一套盤點程式都要同一份清單，把邏輯放進資料庫（預存程序）或放在應用程式裡各寫一次，課堂沒有比較優劣。你只能根據「重複利用」這句話，寫出你傾向哪邊，以及這個傾向超出本堂證據的地方。

## 11. Retrieval Practice — 請先作答

**Why.** ANSI、ISO 為什麼要為 SQL 訂標準？若沒有標準，老師認為這套語法的後續發展會怎樣？

**How.** 預存程序要能被別人方便呼叫，課堂說要先完成哪幾件事？函式在課堂裡用哪兩個特徵來認？

**Trade-off.** 只用標準 SQL，和把重複邏輯寫成某廠商的預存程序，各換到什麼、各輸掉什麼？選錯時，具體會卡在哪？

**Prediction.** 一句全小寫的標準 `select`，以及一段 Transact-SQL 預存程序，分別拿到另一家資料庫執行。兩件事的結果為什麼不該用同一句「都是 SQL」來預測？

**Application.** 你在 MySQL 寫會重複使用的庫存計算。文件標題要不要寫成 PL-SQL 或 Transact-SQL？若半年後可能換 SQL Server，這段計算該先當標準查詢還是先當 MySQL 預存程序？用本堂的相容性說法回答。

## 12. 下一步

學完本堂，你應該能：

- 用一句話說出 SQL 是什麼、它服務哪一類資料庫。
- 看到大小寫不同的同一句 SQL，能判斷語法層會不會把它們當成不同語言。
- 把「標準 SQL」和「廠商擴充」分開，並指出擴充常落在函式與預存程序。
- 說明 Oracle、SQL Server 的擴展語言有名稱，MySQL 有擴展但課堂說沒有特別名稱。
- 用「重複利用、放進資料庫、取名再呼叫」解釋預存程序；函式則是有小括號、多半計算或回傳。

接著值得學的三個觀念，都接在本堂停住的地方：

1. **實際下 SQL 指令。** 本堂只建立語言身分和標準／擴充的分界，還沒有任何查詢。接下來才是用 SQL 把表裡的資料取出來。
2. **MySQL 裡的函式怎麼呼叫。** 課堂只給了「有小括號、多半計算或回傳」。真的寫查詢時，會碰到內建函式長什麼樣子、回傳值放在結果的哪一欄。
3. **MySQL 的預存程序。** 課堂已說 MySQL 有自己的寫法、只是沒取正式名稱。接下來才是：寫好、放到這個資料庫、命名、呼叫，實際長什麼樣子；以及它和 Transact-SQL／PL-SQL 不能當同一份稿子用。

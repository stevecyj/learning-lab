# 9-2 SQL 語法的種類

來源：`9-2-SQL語法的種類.vtt`

這堂課把 SQL 語法分成四大類：DDL、DML、DQL、DCL。重點在分清哪一句在做結構定義、哪一句在改資料值、哪一句純查詢、哪一句管權限。

---

## 1. 這堂課真正要解決的問題

SQL 指令操作的層級不同：有的在建空表、有的在塞資料、有的只讀不改、有的在管帳號能不能碰。

如果把結構、資料值、查詢與權限混在一起，建表時會誤以為資料已經存在，刪資料時可能誤砍整張表，或者給了應用程式過大的破壞權限。

分清這四大類，才能在對的階段用對的語法，並在權限控制上把風險隔開。

---

## 2. 核心概念

### 概念 1：資料定義語言（DDL, Data Definition Language）

- **它是什麼**：用來建立、修改與移除資料庫及資料庫物件（如 Table）結構的語法。
- **為什麼存在**：在放進任何資料前，必須先定義容器規格（表名、欄位名、型別）。
- **解決什麼問題**：定義結構骨架。在此階段跟資料值還沒有直接關係，表內尚未有任何一筆實際資料。
- **包含指令**：
  - `CREATE`：建立／定義資料庫或表格等物件。
  - `ALTER`：修改既有的定義。
  - `DROP`：移除既有的定義。
- **何時使用**：規劃或調整資料庫、資料表的結構規格時。
- **何時不適合使用**：要新增、修改或讀取實際資料列時，不使用 DDL。

### 概念 2：資料處理語言（DML, Data Manipulation Language）

- **它是什麼**：表格建立好後，用來對裡面的資料值本身進行新增、修改與刪除的語法。
- **為什麼存在**：有了結構後，應用程式需要對裡面的實際數值進行日常維護。
- **解決什麼問題**：處理資料列的值：新增一筆資料、修改一筆資料、刪除一筆資料。
- **包含動作**：新增（Insert）、修改（Update）、刪除（Delete）。
- **何時使用**：表格結構已存在，需要寫入、更新或移除資料時。
- **何時不適合使用**：想要改變欄位名稱、型別或刪除整張表結構時，不使用 DML。

### 概念 3：資料查詢語言（DQL, Data Query Language）

- **它是什麼**：以「查詢」為主的語法，核心指令是 `SELECT`。
- **為什麼存在**：讀取與檢視資料是資料庫最頻繁的操作，因此將唯讀查詢獨立分類。
- **解決什麼問題**：從已存在的表格中篩選並取得資料，不更動資料本身。
- **歷史演進與歸類差異**：
  - **早期觀點**：有些人把 `SELECT` 歸在 DML 底下。
  - **現代分類**：現在大部分都獨立拉出來稱為 DQL（老師口誤提到的 dbl 即為 DQL）。
- **何時使用**：需要檢視、讀取或檢索資料庫內容時。
- **何時不適合使用**：需要對資料列寫入變更或調整結構時。

### 概念 4：資料控制語言（DCL, Data Control Language）

- **它是什麼**：針對使用者進行授權與權限控制的語法。
- **為什麼存在**：多使用者環境下，需要限制哪些帳號能存取哪些資料庫或表格。
- **解決什麼問題**：授權使用者可以使用哪些資料庫物件、存取哪些 Table 裡的資料。
- **包含指令**：
  - `GRANT`：授予使用者特定權限。
  - `REVOKE`：取消／撤銷使用者的特定權限。
- **何時使用**：需要設定或回收帳號對特定物件的存取權限時。
- **何時不適合使用**：單純讀寫業務資料或變更表結構時。

## 3. Mental Model

SQL 四大語法對應到「安全管制」、「結構架構」、「資料更動」到「資料檢索」四個層次：

```text
               ┌─────────────────────────────────────────────────────────┐
               │                資料控制語言 (DCL)                       │
               │        控制誰能碰到物件：GRANT / REVOKE                 │
               └──────────────────────────┬──────────────────────────────┘
                                          │ 允許存取
                                          ▼
┌────────────────────────────────────────────────────────────────────────┐
│                        資料定義語言 (DDL)                              │
│         定義結構骨架（尚無資料值）：CREATE / ALTER / DROP               │
│         [ 資料庫 Database ] ──► [ 資料表 Table (欄位名稱, 型別) ]      │
└─────────────────────────────────────────┬──────────────────────────────┘
                                          │ 結構建立完成
                                          ▼
┌────────────────────────────────────────────────────────────────────────┐
│                        資料處理與查詢層                                │
│                                                                        │
│   【DML 資料處理語言】                   【DQL 資料查詢語言】          │
│   寫入／更動資料值本身                   唯讀檢索資料內容              │
│   （新增、修改、刪除資料列）             （SELECT）                    │
└────────────────────────────────────────────────────────────────────────┘
```

1. **先有骨架（DDL）**：用 `CREATE` 規劃欄位與型別，此時裡面沒有任何資料。要改結構用 `ALTER`，移除結構用 `DROP`。
2. **安全把關（DCL）**：用 `GRANT` 與 `REVOKE` 決定哪些使用者可以操作這些結構與資料。
3. **注入與更動內容（DML）**：骨架建好後，處理資料值的新增、修改與刪除。
4. **讀取檢索（DQL）**：用 `SELECT` 讀取資料。早期常與 DML 混稱，現代多獨立為 DQL。

## 4. 專家視角

### 初學者需要知道，但資深工程師通常不會特別思考的內容

- **DDL 操作結構，DML/DQL 操作資料值**：初學者容易分不清 `DROP TABLE`（DDL，砍掉整張表結構與內容）和 `DELETE`（DML，刪除表內的資料列，表結構還在）。
- **`SELECT` 的分類歸屬**：看到舊教科書把 `SELECT` 算在 DML 不必困惑，早期常合在一起，現代多獨立為 DQL。

### 即使是資深工程師仍然會注意的內容

- **權限最小化原則（DCL 的運用）**：生產環境的應用程式連線帳號，通常只給 DML（新增/修改/刪除）與 DQL（`SELECT`）權限，嚴格禁止給 DDL（`DROP`/`ALTER`）與 DCL 權限，避免因 SQL 注入或程式錯誤導致表結構被破壞。
- **DDL 變更的代價**：修改表結構（`ALTER TABLE`）變更的是底層中繼資料，在大資料量系統中可能引發鎖表或效能衝擊，與日常處理幾筆資料值的 DML 風險完全不同。

## 5. 語法 vs 通用知識

### 語言特有知識

- SQL 語法的四大分類代稱：**DDL**、**DML**、**DQL**、**DCL**。
- 關鍵字對應：
  - DDL：`CREATE`、`ALTER`、`DROP`
  - DML：新增、修改、刪除指令（如 `INSERT`、`UPDATE`、`DELETE`）
  - DQL：`SELECT`
  - DCL：`GRANT`、`REVOKE`

### 通用程式設計知識

- **型別／規格定義 vs 資料實例**：如同程式語言中「類別宣告/型別定義（Class/Type）」與「物件實體（Instance）」的分別；DDL 定義型別與欄位規格，DML 填充實體資料。
- **讀取與寫入分離**：將單純讀取的查詢（Query / Read-only）與會改變系統狀態的寫入更動（Command / Mutation）分開看，對應到 DQL 與 DML 的劃分。
- **存取授權控制（Authorization）**：多使用者系統中，需要透過宣告式機制（如 DCL）管控使用者對資源的操作權限。

## 6. Trade-off

課堂中提及的分類對比與邊界：

| 分類維度 | DDL (資料定義語言) | DML (資料處理語言) | DQL (資料查詢語言) | DCL (資料控制語言) |
| :--- | :--- | :--- | :--- | :--- |
| **操作對象** | 資料庫、資料表等物件結構 | 表格內的「資料值」 | 表格內的「資料值」 | 使用者帳號與權限 |
| **是否影響資料結構** | 是（建立、修改、刪除欄位或表） | 否（結構不變，只動數值） | 否（唯讀） | 否 |
| **核心關鍵字/動作** | `CREATE`, `ALTER`, `DROP` | 新增、修改、刪除資料 | `SELECT` | `GRANT`, `REVOKE` |
| **適用時機** | 建立系統、調整架構規格 | 日常業務資料寫入與更新 | 資料檢視、報表與搜尋 | 帳號權限管理與安全配置 |
| **選錯的後果** | 想刪資料卻下了 `DROP` 會導致整個表格結構消失 | 誤用可能覆蓋或清空重要業務資料 | 唯讀操作，不影響原始資料狀態 | 授權過大會產生資安漏洞，授權不足導致程式無法運作 |

**關於 DQL vs DML 的分類權衡**：
- **將 `SELECT` 納入 DML**：優點是概念統一（凡是操作資料值都算同一類）；缺點是模糊了「唯讀查詢」與「資料變更（新增/修改/刪除）」在安全性與破壞性上的本質差異。
- **將 `SELECT` 獨立為 DQL**：優點是權責分明，明確強調「查詢不具破壞性」；缺點是分類數量增加。

## 7. 常見誤解

1. **以為寫 DDL 時表格裡面就已經有資料了。**
   - 課堂特別強調：DDL 只是在定義表名、欄位名與型別，此時根本還沒有任何一筆資料新增進去。
2. **把 `DROP`（移除結構）與 `DELETE`（刪除資料值）混為一談。**
   - `DROP` 屬於 DDL，移除的是「定義與結構」；刪除資料值屬於 DML，表格結構依然保留。
3. **看到不同教材將 `SELECT` 歸在 DML 就覺得講錯了。**
   - 早期分類常將 `SELECT` 算入 DML，現代習慣則獨立拉出為 DQL，兩者是分類演進的差異。
4. **以為 DCL 是在處理業務資料的計算或篩選。**
   - DCL 完全不處理業務資料，它專注於使用者對資料庫物件的「存取授權（GRANT）」與「取消授權（REVOKE）」。

## 11. Retrieval Practice — 請先作答

**Why.** 為什麼資料定義語言（DDL）在執行時「跟資料值本身還沒有直接關係」？請用建立表格的過程說明。

**How.** 當資料庫表格結構已經定義好之後，若要對裡面的資料進行新增、修改、刪除，依據課堂分類應該使用哪一類語法？

**Trade-off.** 早期有人將 `SELECT` 歸類為 DML，現代則多獨立為 DQL。將「資料查詢」獨立出來分類有什麼好處？

學完本堂課，你應該具備以下理解能力：

- 能夠清楚說出 SQL 語法的四大分類（DDL、DML、DQL、DCL）及其英文全名與代表意涵。
- 能夠依據操作目標（結構、資料值、查詢、權限）精準區分 `CREATE`/`ALTER`/`DROP`（DDL）、新增/修改/刪除（DML）、`SELECT`（DQL）與 `GRANT`/`REVOKE`（DCL）。

接下來值得銜接的學習重點：

1. **DDL 實作：建立與刪除資料庫及資料表**：本堂提到了 `CREATE`、`ALTER`、`DROP`，後續單元將實際學習如何寫出完整的 DDL 語法來建置資料庫與表格。
2. **DML 實作：新增、修改與刪除資料列**：學習如何在建立好的表格中，使用 SQL 語句實際操作資料值。

# 開啟與儲存 SQL 檔案

說明如何在 MySQL Workbench 中建立、儲存與開啟 `.sql` 檔案，並釐清編輯分頁、本機檔案與資料庫伺服器執行的差別。

---

## 1. 這堂課真正要解決的問題

在 MySQL Workbench 中，剛打開的 SQL 編輯分頁只存在於記憶體中。

如果只在分頁裡寫 SQL 並執行，一旦關閉分頁或軟體重開，寫好的語法就會消失；反過來，如果只把 SQL 存成檔案卻沒有點執行，資料庫伺服器也不會有任何改變。

本課要解決兩個問題：
1. **保存與重用 SQL**：把寫好的語法存成 `.sql` 檔案，日後可以重複開啟與執行。
2. **分清存檔與執行**：存檔是把文字寫入本機硬碟，執行是把指令送進 MySQL 伺服器，兩者互不相干。

---

## 2. 核心概念

### 概念一：SQL 腳本檔案是純文字檔 (`.sql` Plain Text File)
- **它是什麼**：以 `.sql` 為副檔名的純文字檔案，裡面記錄一或多條 SQL 指令。
- **為什麼存在**：讓 SQL 指令能以通用文字格式保存在硬碟中，脫離特定 IDE 的限制。
- **解決什麼問題**：避免指令隨分頁關閉而遺失，並讓 SQL 能夠跨工具傳遞與納入 Git 版本控制。
- **何時使用**：撰寫資料庫初始化（DDL）、資料遷移（Migration）、預設資料插入（Seed Data）或常用查詢時。
- **何時不適合使用**：檔案若包含帳號密碼等敏感連線資訊，不可直接提交至公開版本控制庫。

### 概念二：存檔與執行各自獨立 (File Saving vs. Query Execution)
- **它是什麼**：
  - **儲存腳本（Save Script）**：把編輯器內的文字寫入本機硬碟（檔案 I/O）。
  - **執行指令（Execute）**：把編輯器內的文字透過連線發送到 MySQL Server 執行（變更資料庫狀態）。
- **為什麼存在**：Workbench（開發工具）與 MySQL Server（資料庫伺服器）是兩個獨立運行的程式。
- **解決什麼問題**：避免誤以為「存檔就代表資料庫建好了」，或是「執行成功就代表程式碼已經存檔」。
- **何時使用**：寫完需要保留的 SQL 時，既要執行驗證結果，也要存檔留底。
- **何時不適合使用**：單純在分頁裡做臨時一次性的語法測試時，不一定要存檔。

### 概念三：編輯分頁只是記憶體暫存區 (Workbench Editor Tab Buffer)
- **它是什麼**：Workbench 啟動時或點擊工具列「+」號建立的 SQL 分頁，是記憶體中的暫存文字區。
- **為什麼存在**：提供隨開隨寫的工作區，不用每次都先在硬碟建實體檔案才能寫 SQL。
- **解決什麼問題**：方便快速測試語法與同時處理多個不同查詢。
- **何時使用**：需要開新查詢、臨時驗證語法或處理不同任務時。
- **何時不適合使用**：正式的建表或專案初始化腳本，不能只留在未存檔的分頁中。

## 3. Mental Model

### 編輯分頁、本機硬碟與資料庫伺服器的運作流程

```
                  ┌─────────────────────────────────────┐
                  │        MySQL Workbench (RAM)        │
                  │                                     │
                  │   [ + ] 建立空白分頁 (Untitled Tab)   │
                  │   輸入: CREATE SCHEMA bookshop;     │
                  └───────┬─────────────────────┬───────┘
                          │                     │
      [ File -> Save Script ]        [ 點擊閃電 Execute ]
      (寫入硬碟純文字)                      (透過網路送出指令)
                          │                     │
                          ▼                     ▼
             ┌────────────────────────┐  ┌─────────────────────────┐
             │ 本機檔案系統 (Disk)     │  │   MySQL Server (Engine)  │
             │                        │  │                         │
             │  檔案：test.sql        │  │  建立資料庫實體結構     │
             │  內容：純文字 SQL       │  │  名稱：bookshop         │
             └────────────┬───────────┘  └─────────────────────────┘
                          │
             [ File -> Open SQL Script ]
             (從硬碟讀取純文字載入分頁)
                          │
                          ▼
             ┌────────────────────────┐
             │ Workbench 重新載入分頁  │
             │ 可再次檢視、修改或執行 │
             └────────────────────────┘
```

- **儲存（Save）**：RAM ──► Disk（伺服器無任何動作）
- **執行（Execute）**：RAM ──► MySQL Server（硬碟無任何寫入）
- **開啟（Open）**：Disk ──► RAM（伺服器無任何動作，載入後需手動點執行才會生效）

## 4. 專家視角

### 初學者需要知道，但資深工程師通常不會特別思考的內容
1. **`.sql` 就是純文字檔**：可以用 VS Code、記事本或 Vim 開啟，副檔名主要是讓編輯器識別語法並啟用高亮。
2. **工具列「+」號只是開分頁**：這是在記憶體開空白編輯區，硬碟上還沒有實體檔案。
3. **儲存位置自由**：`.sql` 檔案存在本機任何資料夾都可以，不需要放在 MySQL 伺服器的資料目錄。

### 即使是資深工程師仍然會注意的內容
1. **納入 Git 版本控制**：所有的建表與初始化 `.sql` 腳本都應放入 Git 倉庫，追蹤變更紀錄並進行 Code Review。
2. **檔案編碼統一為 UTF-8**：存檔時使用 UTF-8 編碼，避免腳本內的中文註解或預設資料在 Linux 伺服器或 CLI 執行時變成亂碼（*延伸知識*）。
3. **可透過命令列獨立執行**：寫腳本時確保能用 `mysql -u root -p < test.sql` 或 `source` 指令直接跑完，不依賴圖形介面手動點選（*延伸知識*）。

## 5. 語法 vs 通用知識

| 分類 | 具體內容 | 通用程式設計對應觀念 |
| :--- | :--- | :--- |
| **Workbench 操作** | 工具列「+」（新增分頁）<br>`File -> Save Script`<br>`File -> Open SQL Script` | 整合開發環境（IDE）中的檔案緩衝區管理與檔案對話框操作。 |
| **MySQL 慣用語法** | `.sql` 副檔名、結尾分號 `;` | 特定語言原始碼的副檔名規範與語句終結符（Statement Terminator）。 |
| **通用觀念** | **原始碼持久化** | 程式邏輯應以可讀純文字保存於磁碟，而非停留在執行期記憶體。 |
| **通用觀念** | **執行期與原始碼分離** | 程式碼儲存（檔案 I/O）與程式碼執行（Runtime Engine）分屬不同系統層級。 |
| **通用觀念** | **宣告式環境重現** | 透過文字腳本定義環境結構，達成跨機器、跨環境的可重現性。 |

## 6. Trade-off

### 比較：未存檔的臨時分頁 vs 儲存為 `.sql` 檔案

| 比較項目 | 臨時分頁 (Scratchpad) | 儲存為 `.sql` 檔案 |
| :--- | :--- | :--- |
| **建立成本** | 極低（點「+」即寫） | 低（需選擇目錄與命名檔案） |
| **持久性** | 無（關閉分頁或軟體當機即遺失） | 高（安全儲存在硬碟） |
| **重現與重用** | 差（需每次重新手動鍵入） | 佳（隨時以 `Open SQL Script` 重新載入） |
| **版本控制** | 無法加入 Git | 可直接加入 Git 進行協作與版本比對 |
| **適用場景** | 一次性除錯、臨時驗證單行語法 | 資料庫建置腳本、專案遷移、標準測試資料 |

## 7. 常見誤解

### 誤解一：執行了 `CREATE SCHEMA bookshop;` 且成功建庫，Workbench 就會自動幫我存檔？
> **事實**：執行只會讓 MySQL 伺服器建立資料庫；編輯區的文字仍在記憶體中。沒按 `Save Script`，關掉分頁後文字就沒了。

### 誤解二：把寫好的 SQL 存成 `init.sql`，資料庫就建好了？
> **事實**：存檔只是把文字寫進本機硬碟，沒有送任何指令給 MySQL 伺服器。必須按執行按鈕（閃電），資料庫才會真正建立。

### 誤解三：`.sql` 檔案是特殊二進位檔，只能用 Workbench 開啟？
> **事實**：`.sql` 是標準純文字檔，任何文字編輯器（VS Code、記事本、Vim）都能打開與修改。

### 誤解四：點擊工具列「+」號，硬碟上就會自動新增檔案？
> **事實**：「+」號只是在 Workbench 裡開一個暫存編輯分頁（Untitled），直到按存檔指定路徑前，硬碟都不會有實體檔案。

## 10. Coding Challenge

### 目標：標準 SQL 腳本建立、持久化與載入驗證流程
模擬專案資料庫初始化流程，完成以下工作：

1. **建立腳本**：在 Workbench 建立一個全新空白 SQL 分頁。
2. **撰寫 DDL 語句**：
   - 撰寫建立資料庫 `bookstore_v1` 的 SQL 語法。
   - 每行語句結尾須有標準分號 `;`。
3. **持久化存檔**：
   - 使用 `File -> Save Script` 將該腳本儲存為本機檔案 `init_bookstore.sql`。
4. **執行與驗證**：
   - 執行該腳本，確認 MySQL 伺服器建立 `bookstore_v1` 資料庫。
5. **重現測試**：
   - 關閉該 SQL 編輯分頁。
   - 使用 `File -> Open SQL Script`（或工具列開啟按鈕）重新載入 `init_bookstore.sql`。
   - 確認文字完整載入，無內容缺失。
6. **挑戰延伸 (Stretch Goal)**：
   - 在腳本開頭加入多行註解（`/* ... */`），註明專案名稱、作者與建立日期。
   - 將檔案改用純文字編輯器（如 VS Code）開啟，確認純文字內容可跨工具正常讀取。
